# Rocket Start 기반 동시다발 업무 처리 스킬

> **이 파일은 로켓스타트 철학의 단일 출처(SSOT)다.**
> `rocket-orchestrator`와 triage·slot·brief 에이전트가 작업 전 이 파일의 철학을 읽어 판단을 끌어낸다.
> 운영 방식을 바꾸려면 다른 곳이 아니라 이 파일을 수정한다.

## 목적
이 스킬의 목적은 여러 업무를 동시에 진행해야 하는 상황에서, 모든 일을 한꺼번에 수행하려 하지 않고 **병목을 먼저 깨고, 나머지 업무는 추적 가능한 상태로 관리하면서, 실제 실행은 순차적으로 밀어내는 방식**으로 일정을 운영하도록 돕는 것이다.

이 스킬은 태스크 자체를 잘게 쪼개는 것보다, **여러 업무가 동시에 존재하는 환경에서 무엇을 먼저 착수하고, 무엇을 깊게 진행하고, 무엇을 열어만 둘지 판단하는 운영 방식**에 초점을 둔다.

---

## 이 스킬이 다루는 문제
다음과 같은 상황에서 사용한다.

- 여러 업무가 동시에 들어와 있고, 모두 중요해 보여서 무엇부터 해야 할지 모를 때
- 하나의 업무를 깊게 하려 하면 아직 시작도 못 한 다른 업무가 계속 신경 쓰일 때
- 병목이 큰 업무를 먼저 처리해야 하는데, 쉬운 일이나 급해 보이는 일로 자꾸 도망가게 될 때
- 하루 종일 바빴는데 실제 핵심 진도가 거의 나가지 않았을 때
- 일정표는 있어도, 어떤 업무를 언제 착수하고 언제 깊게 밀어야 하는지가 불명확할 때

---

## 핵심 철학
이 스킬은 아래 원칙을 따른다.

1. **여러 업무를 동시에 실행하지 않는다.**  
   여러 업무는 동시에 추적할 수 있지만, 깊은 실행은 한 번에 하나씩 한다.

2. **가장 먼저 병목을 깬다.**  
   초반에는 가장 불확실하고 전체 일정을 흔들 수 있는 업무를 먼저 열어 범위와 리스크를 드러낸다.

3. **로켓스타트는 ‘빠르게 시작’이 아니라 ‘초반 추진력 확보’다.**  
   가장 중요한 업무에 초반 좋은 시간을 집중해, 시작 장벽을 넘고 이후 실행 비용을 낮춘다.

4. **전체 일정은 균등 분배가 아니라 상태 기반 운영으로 본다.**  
   모든 업무를 같은 비율로 나누지 말고, ‘이미 범위가 보이는 일’, ‘지금 착수해야 리스크가 줄어드는 일’, ‘아직 열지 않아도 되는 일’로 분리한다.

5. **공부나 조사도 실행을 위한 최소 단위로 한다.**  
   충분히 이해한 뒤 시작하는 것이 아니라, 시작하고 필요한 만큼만 조사한다.

---

## 업무 분류 체계
동시에 존재하는 업무는 아래 3가지 층으로 분류한다.

### 1층. 실행 가능한 업무
이미 한 번 로켓스타트를 거쳐서 범위, 병목, 다음 작업, 공수의 윤곽이 보이는 업무.

예시:
- API 공수 산출 초안이 잡혀 있어서 실제 수정 순서와 테스트 순서를 정할 수 있는 상태
- 프로토타입 스펙이 정리되어 있어서 구현을 시작할 수 있는 상태

이 업무는 **실행 슬롯**에 넣는다.

### 2층. 빠르게 착수해야 하는 업무
아직 본격 시작은 안 했지만, 짧게라도 열어보지 않으면 나중에 더 큰 리스크가 될 업무.

예시:
- 데이터 병합 가능 여부가 불명확한 모델링 업무
- 외부 연동 설계안이 필요한 조사 업무
- 서버 운영 구조를 정해야 하는 기술 조사 업무

이 업무는 **착수 슬롯**에 넣는다.

### 3층. 아직 열지 않아도 되는 업무
중요할 수는 있지만, 지금 당장 실행 슬롯이나 착수 슬롯을 줄 필요가 없는 업무.

예시:
- 리팩토링
- 문서 polish
- 구조 미화
- 품질 개선
- 후순위 추가 기능

이 업무는 **추적만 하고 실행하지 않는다.**

---

## 슬롯 기반 운영 원칙
하루는 아래 2가지 슬롯으로 운영한다.

### 1. 실행 슬롯
이미 범위가 보이는 업무를 실제로 앞으로 미는 시간.

이 슬롯에서는 다음을 한다.
- 구현
- 수정
- 테스트
- 문서 확정
- 공수 정리
- 결과물 생성

원칙:
- 하루에 실행 슬롯은 **1개 업무만** 가진다.
- 가장 좋은 시간대(예: 오전 첫 60~90분)를 여기에 사용한다.
- 이 시간에는 메신저, 메일, 사소한 수정, 다른 업무 탐색을 금지한다.

### 2. 착수 슬롯
아직 시작하지 않은 업무를 짧게 열어, 범위와 리스크를 드러내는 시간.

이 슬롯에서는 다음만 한다.
- 목표 정의
- 최소 입력 목록 확정
- 흐름 초안 작성
- 병목 확인
- 다음 행동 정의

원칙:
- 하루에 착수 슬롯은 **최대 1개 업무만** 가진다.
- 30~60분 내로 끊는다.
- 결과물 없이 끝내지 않는다.
- 반드시 다음 행동 1개를 남긴다.

## 로켓스타트 적용 방식
새로운 업무를 처음 열 때는 아래 형식으로 로켓스타트를 적용한다.

### 로켓스타트 템플릿
1. 이 업무의 목적은 무엇인가?
2. 완료 상태는 무엇인가?
3. 현재 가장 큰 병목은 무엇인가?
4. 첫 60~90분 안에 남길 수 있는 최소 산출물은 무엇인가?
5. 이 업무는 지금 실행 슬롯으로 가야 하는가, 착수 슬롯으로만 충분한가?

### 로켓스타트 결과물 예시
- API 흐름도 초안
- 문제 인벤토리 표
- 입력 데이터 목록표
- 학습용 테이블 schema
- 설계안 목차
- 공수산출 WBS 초안

중요한 점은, 로켓스타트의 목표가 **완성**이 아니라 **불확실성 제거와 추진력 확보**라는 것이다.

## 전체 일정 운영 규칙
여러 업무를 병행할 때는 다음 순서로 판단한다.

### Step 1. 현재 업무를 상태별로 나눈다
각 업무를 아래 중 하나로 분류한다.
- 실행 가능한가?
- 짧게라도 착수해야 하는가?
- 지금은 열지 않아도 되는가?

### Step 2. 이번 주 실행 슬롯의 주인공을 정한다
이번 주 실제 진도를 만들어야 하는 핵심 업무 1개를 정한다.

판단 기준:
- 이미 범위가 어느 정도 보이는가
- 마감과 직접 연결되는가
- 지금 미루면 다른 업무까지 흔드는가

### Step 3. 아직 미착수인 업무는 순서대로 착수 슬롯에 넣는다
착수 슬롯의 목적은 완료가 아니다.
아직 시작도 못 한 업무를 ‘막연한 상태’에서 ‘다음 행동이 보이는 상태’로 옮기는 것이다.

### Step 4. 매일 “실행 1개 + 착수 1개”만 고른다
- 오전: 실행 슬롯 1개
- 오후 짧은 블록: 착수 슬롯 1개

이 구조를 넘어서면 맥락 전환 비용이 급격히 올라간다.

### Step 5. 하루 종료 전, 다음 행동을 남긴다
모든 업무는 종료 시 아래 3개를 남긴다.
- 현재 상태
- 다음에 바로 할 1개
- 막히는 이유 또는 리스크 1개

이게 없으면 다음날 같은 업무를 다시 열 때 재시작 비용이 커진다.

---

## 판단 기준
아래 질문을 매일 아침 스스로에게 적용한다.

1. 오늘 깊게 팔 1개는 무엇인가?
2. 아직 시작 안 한 일 중 오늘 1개만 열어볼 것은 무엇인가?
3. 오늘 절대 손대지 않을 일은 무엇인가?
4. 지금 하고 싶은 일이 진짜 핵심인가, 아니면 쉬워 보여서 도망가고 있는 것인가?
5. 이 업무는 더 생각해야 하는가, 아니면 지금 바로 최소 산출물을 만들어야 하는가?

---

## 금지 규칙
다음 행동은 피한다.

- 모든 업무를 하루에 조금씩 건드리기
- 시간표를 먼저 정하고 우선순위를 나중에 생각하기
- 착수 슬롯을 조사만 하다가 끝내기
- 실행 슬롯에 두 개 이상의 업무를 넣기
- 좋은 아이디어가 떠올랐다는 이유로 이미 진행 중인 핵심 업무를 중단하기
- 결과물이 없는 ‘생각만 한 시간’을 생산으로 간주하기

## 출력 형식
이 스킬을 사용할 때는 항상 아래 형식으로 정리한다.

### 1. 업무 상태 분류
- 실행 가능한 업무
- 착수 필요한 업무
- 지금 열지 않을 업무

### 2. 오늘의 실행 슬롯
- 대상 업무
- 이유
- 첫 60~90분 목표
- 완료 기준

### 3. 오늘의 착수 슬롯
- 대상 업무
- 이유
- 첫 30~60분 목표
- 남겨야 할 최소 산출물

### 4. 미착수 업무 처리 순서
- 어떤 순서로 열 것인지
- 각 업무의 첫 착수 목표는 무엇인지

### 5. 리스크
- 범위 과대화
- 조사 과잉
- 완벽주의
- 맥락 전환
- 아직 결정되지 않은 정책/외부 의존성

## 클로드 코드용 스킬 프롬프트
아래 프롬프트를 그대로 붙여 넣어 사용할 수 있다.

```md
너의 역할은 여러 업무를 동시에 수행해야 하는 사용자의 업무 운영 코치다.

목표는 사용자가 모든 업무를 한꺼번에 처리하려 하지 않도록 하고,
Rocket Start 방식으로 가장 큰 병목을 먼저 깨고,
이후에는 여러 업무를 동시에 추적하되 실제 실행은 순차적으로 진행할 수 있도록
전체 일정을 상태 기반으로 재구성하는 것이다.

다음 원칙을 반드시 따른다.

1. 업무를 먼저 상태별로 분류한다.
- 실행 가능한 업무
- 빠르게 착수해야 하는 업무
- 지금은 열지 않아도 되는 업무

2. 하루 계획은 반드시 아래 두 슬롯으로 나눈다.
- 실행 슬롯: 이미 범위가 보이는 업무를 깊게 진행하는 시간
- 착수 슬롯: 아직 시작 안 한 업무를 짧게 열어 범위와 리스크를 드러내는 시간

3. 실행 슬롯은 하루에 1개만 둔다.
4. 착수 슬롯도 하루에 최대 1개만 둔다.
5. 모든 업무를 동시에 조금씩 하라고 제안하지 않는다.
6. 항상 “무엇을 먼저 해야 하는가”보다 “왜 그 순서가 맞는가”를 함께 설명한다.
7. 사용자가 제시한 업무들을 보고, 병목/불확실성/선행조건/마감 영향도를 기준으로 우선순위를 재구성한다.
8. 각 업무에 대해 첫 60~90분 안에 남길 최소 산출물을 정의한다.
9. 결과는 보고용이 아니라 실행용이어야 한다.
10. 항상 마지막에 아래 3개 질문을 던진다.
- 오늘 깊게 팔 1개는 무엇인가?
- 아직 시작 안 한 일 중 오늘 1개만 열어볼 것은 무엇인가?
- 오늘 절대 손대지 않을 일은 무엇인가?

출력은 아래 형식으로 한다.

# 1. 업무 상태 분류
# 2. 실행 슬롯 제안
# 3. 착수 슬롯 제안
# 4. 업무별 첫 착수 산출물
# 5. 이번 주 운영 원칙
# 6. 리스크와 회피 포인트
# 7. 오늘의 질문 3개
```

## 추천 사용 예시
이 스킬은 아래처럼 사용할 수 있다.

### 예시 1
“내가 이번 주에 해야 할 5개 업무를 줄 테니, Rocket Start 기반으로 실행 슬롯과 착수 슬롯으로 나눠줘.”

### 예시 2
“지금 하나는 이미 범위와 공수가 보이고, 나머지 3개는 미착수 상태야. 어떤 순서로 열어야 할지 정리해줘.”

### 예시 3
“내 업무 리스트를 보고 오늘 오전에는 무엇을 깊게 하고, 오후에는 무엇을 짧게 착수해야 하는지 실행용으로 정리해줘.”

## 한 줄 요약
이 스킬은 여러 업무를 동시에 처리하는 방법이 아니라,
**여러 업무가 동시에 존재하는 상황에서도 실제 실행은 하나씩 밀어내도록 업무를 재배치하는 운영 스킬**이다.
