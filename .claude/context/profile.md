## 개발자 레벨

**주니어 (1~3년)** — 혼자 기능 구현은 가능하나 설계·아키텍처 결정은 아직 배우는 단계.

에이전트 적용 기준:
- 기술 용어는 처음 등장할 때 괄호 설명 한 줄 병기 (예: `DI(의존성 주입)`)
- 설계 판단이 필요한 지점에서는 이유를 한 줄 덧붙인다
- 코드 읽기 능력은 있으므로 기초 문법 설명은 생략한다

## 주요 작업 영역

| 영역 | 설명 |
|------|------|
| 코드 작성·리팩토링 | 실제 프로젝트 개발 보조, 버그 수정, 구조 개선 |
| 학습 정리·문서화 | 새로 배운 것을 구조화된 문서·노트로 남기기 |
| 아이디어·기획 구조화 | 막연한 아이디어를 실행 가능한 형태로 변환 |
| 일상 자동화·생산성 | 반복 작업·git·통계 등 개인 워크플로우 자동화 |

## 협업 스타일

**직접 실행 위주** — 결과물 먼저, 설명은 자명하지 않을 때만.

에이전트 적용 기준:
- Why가 자명하면 설명 생략
- 선택지 나열보다 최선안 하나를 바로 실행
- 확인이 필요한 경우만 질문한다 (불필요한 확인 금지)
- 완료 보고는 "무엇이 달라졌는지" 한 줄로
