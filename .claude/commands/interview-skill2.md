계획·설계의 모든 측면을 의존성 순서에 따라 하나씩 질문하며 완전한 합의에 도달합니다.
질문마다 추천 답변을 함께 제시하고, 모든 분기가 해소될 때까지 멈추지 않습니다.

## 입력

$ARGUMENTS

---

## /interview와의 차이

| | /interview | /interview-skill2 |
|---|---|---|
| 목적 | 모호함 → 브리프 (빠른 수렴) | 계획 → 완전한 합의 (철저한 탐색) |
| 방식 | 가설 제시 후 반응 관찰 | 질문 + 추천 답변, 하나씩 |
| 깊이 | 최대 3라운드 | 모든 분기가 해소될 때까지 |
| 대상 | 형태가 없는 아이디어 | 이미 방향이 있는 계획·설계 |

---

## 실행 절차

### 0. 입력 확인

`$ARGUMENTS`가 비어 있으면 아래를 출력하고 종료하세요.

```
사용법: /interview-skill2 <계획이나 설계>
예시:   /interview-skill2 카카오톡 파일 자동 정리 시스템 만들기
        /interview-skill2 개인 블로그 개발 계획
        /interview-skill2 팀 코드 리뷰 프로세스 개선
```

### 1. 설계 트리 구축 (출력하지 않음, 내부 작업)

입력을 받아 아래 구조로 설계 트리를 내부적으로 구성하세요.

```
루트: {전체 계획 한 줄}
  ├─ 목적·동기
  │    └─ 왜 만드는가 / 해결하려는 문제
  ├─ 산출물
  │    ├─ 무엇이 만들어지는가
  │    └─ 완료 기준
  ├─ 범위
  │    ├─ 포함할 것
  │    └─ 제외할 것
  ├─ 기술·방법
  │    ├─ 어떤 기술을 쓰는가
  │    └─ 어떤 방식으로 구현하는가
  ├─ 제약
  │    ├─ 기술적 제약
  │    └─ 시간·자원 제약
  └─ 리스크
       ├─ 예상 블로커
       └─ 대안
```

각 노드를 **미결정** 상태로 초기화합니다.

### 2. 의존성 순서 결정 (출력하지 않음, 내부 작업)

아래 원칙으로 질문 순서를 결정하세요.

- 다른 결정의 전제가 되는 것을 먼저 묻는다
- 상위 결정이 하위 결정을 제약한다
- 일반적 순서: 목적 → 산출물 → 범위 → 기술 → 제약 → 리스크

입력에 따라 이미 명확한 노드는 건너뜁니다.

### 3. 시작 안내 출력

```
{입력}에 대해 설계 전반을 하나씩 짚어가겠습니다.
각 질문마다 추천 답변을 함께 드릴게요.
동의하면 "맞아요" / 수정이 있으면 말씀해주세요.

총 {예상 질문 수}개 질문으로 완전한 합의에 도달합니다.
```

### 4. 질문 루프 — 합의 도달까지 반복

아래 형식으로 **한 번에 하나씩** 질문을 출력합니다.
사용자 답변을 받은 뒤 다음 질문으로 넘어갑니다.

```
[{N}/{전체}] {결정 영역}
────────────────────────────────────
질문: {이 시점에서 결정해야 할 핵심 질문}

추천: {권장 방향}
      이유: {왜 이 방향이 좋은지 한 줄}

→ 어떻게 생각하시나요?
```

**답변 처리 기준:**

| 답변 유형 | 처리 방식 |
|-----------|-----------|
| "맞아요" / 동의 | 결정 확정 → 다음 질문으로 |
| 수정 의견 | 수정 내용 반영 확인 후 → 다음 질문으로 |
| "모르겠어요" | 추천 방향으로 잠정 확정 → 다음 질문으로 (나중에 수정 가능) |
| 새로운 측면 제기 | 트리에 새 노드 추가 → 적절한 순서에 삽입 |

### 5. 분기 심화

상위 결정에 따라 하위 질문이 달라지는 경우, 해당 분기를 따라 깊이 탐색합니다.

예시:
```
기술 스택을 Python으로 확정했다면
  → "어떤 파일 감시 라이브러리를 쓸 것인가?" 질문 추가
  → "패키지 관리는 pip인가 poetry인가?" 질문 추가
```

### 6. 합의 완료 출력

모든 노드가 결정되면 아래 형식으로 전체 합의 내용을 출력합니다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
완전한 합의 도달 ({N}개 결정 확정)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 설계 합의서

**목적·동기**
{확정 내용}

**산출물**
{확정 내용}

**범위**
- 포함: {내용}
- 제외: {내용}

**기술·방법**
{확정 내용}

**제약**
{확정 내용}

**리스크 및 대안**
{확정 내용}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
아래 명령으로 바로 시작할 수 있습니다:

/task {설계 합의서를 기반으로 정제한 한 줄 요구사항}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 운영 원칙

- 질문은 반드시 **하나씩** 출력한다. 여러 질문을 한꺼번에 묻지 않는다
- 모든 질문에 **추천 답변과 이유**를 함께 제시한다
- 상위 결정이 확정되기 전에 하위 결정을 묻지 않는다 (의존성 준수)
- 사용자가 이미 명확히 밝힌 내용은 다시 묻지 않는다
- "됐어" / "충분해" / "시작하자"라고 하면 현재까지의 합의로 설계 합의서를 출력하고 종료한다
- 모든 질문과 답변은 **한국어**로 진행한다
